# Функциональная спецификация MAC Analyzer Pro Next

## Назначение

Программа объединяет выгрузки сетевой аутентификации, SmartRoom и DDIO,
формирует текущее состояние оборудования переговорных, сохраняет историю и
показывает изменения между финальными обогащениями.

## 1. Импорт

- Основной файл определяет исходный набор устройств.
- SmartRoom содержит характеристики, помещения и стабильные идентификаторы.
- DDIO содержит четыре колонки: MAC/IP резервации и MAC/IP аренды.
- Поддерживаются CSV, TSV, JSON и первый лист XLSX.
- Для каждого источника колонки определяются автоматически и доступны для
  ручной проверки и изменения.
- Дата наблюдения сначала берётся из имени файла, затем из времени файла.
- Некорректная строка не останавливает весь импорт и попадает в диагностику.

## 2. Стратегии количества устройств

### NO_EXPANSION

Final содержит только уникальные физические устройства основного файла.
SmartRoom и DDIO заполняют атрибуты, но не создают строки.

### ALLOW_EXPANSION

Final начинается с основного файла. SmartRoom может добавить запись, если у неё
есть сильный идентификатор и она не сопоставилась с Main. DDIO никогда не создаёт
устройство автоматически.

## 3. Идентификация

Приоритет признаков:

1. Device ID;
2. серийный номер;
3. основной MAC;
4. дополнительный MAC;
5. hostname как вспомогательный признак;
6. Smartroom ID и IP как слабые признаки.

Совпадение только по IP, IP коммутатора, помещению, модели или производителю не
является основанием для слияния. Неоднозначный результат сохраняется как конфликт.

## 4. Обогащение

- SmartRoom дополняет IP, MAC второго интерфейса, производителя, модель, тип,
  адрес, помещение, Smartroom ID, hostname, serial и Device ID.
- Previous Final восстанавливает только отсутствующие непротиворечивые значения.
- Непустое новое значение имеет приоритет над старым, а пустое не стирает старое.
- OUI определяет производителя по первым трём байтам MAC.
- Известная модель сохраняется по точному MAC и применяется в следующих циклах.
- DDIO ищет основной и дополнительные MAC независимо от IP коммутатора.
- Если IP устройства пуст, а точный MAC имеет единственный IP в DDIO, IP
  записывается в Final с источником `DDIO`.
- Несколько DDIO IP сохраняются как `possibleIps` и конфликт, без случайного выбора.
- Повторное обогащение одинаковых файлов не создаёт новые устройства и историю.

## 5. Постоянное хранение

- Final Snapshot — устройства конкретного успешного цикла.
- Inventory — накопительный реестр всех когда-либо известных устройств.
- History — реальные изменения полей, добавления и отсутствия.
- Known Models — модели, изученные по MAC.
- OUI — локальный справочник производителей.
- Данные хранятся в IndexedDB, а не в localStorage.
- Снимок разбивается на блоки по 500 устройств.
- Сохранение Final, Inventory и History выполняется одной транзакцией.
- Ошибка сохранения оставляет предыдущий Final активным.
- Переносимый архив содержит снимки, inventory, историю, настройки, модели и OUI.

## 6. Поиск и таблица

- Стартовый экран сразу показывает поиск и таблицу Inventory.
- Поиск работает по MAC, альтернативным MAC, IP устройства, IP коммутатора,
  hostname, serial, Device ID, названию, производителю, модели и помещению.
- Таблица имеет пагинацию 50/100/250 строк и сортировку по заголовкам.
- Двойной клик открывает полную карточку устройства.
- CSV выгружает весь отфильтрованный результат, а не только текущую страницу.

## 7. Final-to-Final изменения

- Добавленное устройство отсутствовало в базовом Final и присутствует в новом.
- Отсутствующее присутствовало в базовом Final и отсутствует в новом.
- Изменение фиксируется только при двух известных и разных значениях.
- Пустое поле не создаёт ложное событие `пусто → значение`.
- Критические поля: IP устройства, IP коммутатора, MAC, физический адрес и
  Smartroom ID.
- Источники и альтернативы не увеличивают число фактических изменений.

## 8. Аналитика

- Устройства, изменённые, отсутствующие и неизменившиеся.
- Производители, модели, помещения и устройства без помещения.
- Помещения с любыми изменениями.
- Помещения, в которых изменилось всё оборудование.
- Изменения устройств типа `Video Conference`.
- Недельная динамика изменений MAC с количеством помещений и MAC.
- Добавленные значения показываются выше нуля, отсутствующие — ниже нуля.
- Общее число устройств отображается по всем Final от первого до последнего.
- Повторно исчезающие и возвращающиеся MAC рассчитываются по полной истории.

## 9. Отклонения IP коммутатора внутри помещения

- Помещение группируется по Smartroom ID.
- Если ID отсутствует, используется полный составной ключ ТБ → город → площадка
  → этаж → помещение → адрес.
- Запись без ID объединяется с ID только когда соответствие локации однозначно.
- Если в одной комнате большинство устройств использует один IP коммутатора, а
  часть — другой, комната считается отклонением.
- Карточка `NEW` показывает полный состав: MAC, IP устройства, IP/порт
  коммутатора, производитель, модель, тип, hostname, serial, Device ID,
  Smartroom ID, адрес, время аутентификации и источник.

## 10. Хронология MAC

- Строится по всем последовательным Final.
- Первый снимок показывает заполненное исходное состояние без ложных изменений.
- Далее отображаются все присутствия, реальные изменения и отсутствия.
- Изменённые поля подсвечиваются, рядом сохраняется полная карточка состояния.

## 11. Хронология помещения

- Каскад: ТБ → город → площадка → этаж → помещение.
- Каждый следующий список содержит значения только выбранной ветви.
- Дополнительный поиск работает по названию, адресу и Smartroom ID.
- Для каждого Final показывается полный состав оборудования помещения.
- Отдельная команда показывает комнаты, где изменились все устройства.

## 12. Массовое обогащение

- Пользователь выбирает папки Main, SmartRoom и DDIO.
- Поддерживаются CSV, TSV, JSON и XLSX.
- Основные файлы сортируются по дате.
- Для каждого Main подбирается ближайший по дате SmartRoom и DDIO.
- Перед запуском показывается таблица пар.
- Для каждого файла отдельно выполняется автоопределение колонок.
- Циклы выполняются последовательно, а каждый успешный цикл создаёт Final.
- Ошибка одного цикла не маркирует частичный Final как успешный.

## 13. Экспорт

- CSV и JSON последнего Final.
- CSV результата поиска.
- Переносимый архив всей локальной базы.
- Импорт архива в другой браузер без удаления уже существующих снимков.

## 14. Темы и ошибки

- Светлая и тёмная темы с контрастными цветами текста.
- Все пользовательские операции обёрнуты в обработку ошибок.
- Ошибка показывается в верхнем баннере.
- Прогресс отражает реальные этапы, а не таймер.
- Операцию обогащения можно отменить через AbortController.
