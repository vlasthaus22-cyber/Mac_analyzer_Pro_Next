# Функциональная спецификация MAC Analyzer Pro Next

## Назначение

Программа объединяет выгрузки сетевой аутентификации, SmartRoom и DDIO,
формирует текущее состояние оборудования переговорных, сохраняет историю и
показывает изменения между финальными обогащениями.

## 1. Импорт

- Основной файл определяет исходный набор устройств.
- SmartRoom содержит характеристики, помещения и стабильные идентификаторы.
- DDIO содержит четыре пары MAC/IP резервации и аренды и может содержать
  Device ID для поиска связанных possible IP.
- Поддерживаются CSV, TSV, TXT, JSON, XLS, XLSX и макросодержащий XLSM без выполнения макросов. По умолчанию используется первый лист; в анализе одного файла можно выбрать любой лист XLS/XLSX/XLSM.
- Текст читается как UTF-8, Windows-1251 или UTF-16 по сигнатуре/валидности.
- Автономный импорт ограничен 64 MiB на обычный файл, 16 MiB на старый бинарный XLS, 150 000 строк, 1 500 000 ячеек и 192 MiB распакованного XLSX; превышение останавливается с понятной ошибкой.
- BIFF `.xls` загружается целиком библиотекой декодирования, затем строки выдаются пакетами по 500; preview хранит не больше 80 строк. Для крупных legacy-книг рекомендуются XLSX или CSV.
- Для каждого источника колонки определяются автоматически и доступны для
  ручной проверки и изменения.
- Иерархия ТБ → город → площадка → этаж → помещение извлекается из отдельного
  location path, полного значения колонки помещения или адреса; пустые уровни
  между разделителями сохраняют свои позиции.
- Дата наблюдения берётся из имени файла; если даты нет, XLS/XLSX/XLSM использует
  метаданные `created`, затем `modified`, а прочие файлы —
  `lastModified`.
- Некорректная строка не останавливает весь импорт и попадает в диагностику.

## 2. Стратегии количества устройств

### NO_EXPANSION

Final содержит только уникальные физические устройства основного файла.
SmartRoom и DDIO заполняют атрибуты, но не создают строки.

### ALLOW_EXPANSION

Final начинается с основного файла. SmartRoom может добавить запись, если у неё
есть сильный идентификатор и она не сопоставилась с Main. DDIO никогда не создаёт
устройство автоматически.

## 3. Идентификация

Приоритет признаков:

1. сохранённый внутренний ID;
2. Device ID;
3. серийный номер;
4. основной MAC;
5. дополнительный MAC;
6. hostname как вспомогательный признак;
7. Smartroom ID и IP как слабые признаки.

Совпадение только по IP, IP коммутатора, помещению, модели или производителю не
является основанием для слияния. Неоднозначный результат сохраняется как конфликт.

## 4. Обогащение

- SmartRoom дополняет IP, MAC второго интерфейса, производителя, модель, тип,
  адрес, помещение, Smartroom ID, hostname, serial и Device ID.
- Previous Final восстанавливает только отсутствующие непротиворечивые значения.
- Непустое новое значение имеет приоритет над старым, а пустое не стирает старое.
- IEEE registry определяет производителя по самому длинному совпавшему
  24-, 28- или 36-битному префиксу MAC; CID остаётся только в метаданных.
- Известная модель сохраняется по точному MAC; встроенные и пользовательские
  правила по первым 4–5 байтам MAC применяются только к пустой модели, с источником.
- DDIO ищет основной и дополнительные MAC независимо от IP коммутатора.
- Если IP устройства пуст, а точный MAC имеет единственный IP в DDIO, IP
  записывается в Final с источником `DDIO`.
- В обычном потоке объединения большие XLSX сначала дают предпросмотр для
  сопоставления колонок, затем строки Main, SmartRoom и DDIO повторно читаются
  пакетами по 500 без полного массива исходной таблицы.
- Массовая очередь перед запуском хранит предпросмотр и mapping файлов, затем
  каждый XLSX-цикл перечитывает исходные листы пакетами отдельно и сохраняет свой
  Final атомарно.
- Несколько DDIO IP сохраняются как `possibleIps` и конфликт, без случайного выбора.
- Повторное обогащение одинаковых файлов не создаёт новые устройства и историю.

## 5. Постоянное хранение

- Final Snapshot — устройства конкретного успешного цикла.
- Inventory — накопительный реестр всех когда-либо известных устройств.
- History — реальные изменения полей, добавления и отсутствия.
- Known Models — модели, изученные по MAC.
- OUI/IEEE — локальный справочник производителей; пользовательский OUI
  перекрывает встроенный IEEE только при совпадении длины и префикса.
- Данные хранятся в IndexedDB, а не в localStorage.
- Снимок разбивается на блоки по 500 устройств.
- Сохранение Final, Inventory, History, derived evidence и исходных Blob Main,
  SmartRoom, DDIO выполняется одной транзакцией.
- Ошибка сохранения оставляет предыдущий Final активным.
- При запуске активная ссылка проверяется по полным чанкам. Потерянная или
  повреждённая ссылка восстанавливается на самый новый целый Final без удаления
  повреждённых пользовательских данных.
- Переносимый архив содержит снимки, исходные файлы, inventory, историю,
  настройки, модели и OUI; байты исходников кодируются потоковыми блоками.
- Импорт проверяет версию, структуру, ID и предел размера до записи; более старый
  архив сохраняет текущий новый Final, непустые известные поля Inventory и настройки.

## 6. Поиск и таблица

- Стартовый экран сразу показывает поиск и таблицу Inventory.
- Поиск работает по MAC, альтернативным MAC, IP устройства, IP коммутатора,
  hostname, serial, Device ID, названию, производителю, модели и помещению.
- Таблица имеет пагинацию 50/100/250 строк и сортировку по заголовкам.
- Двойной клик открывает полную карточку устройства.
- CSV выгружает весь отфильтрованный результат, а не только текущую страницу.

## 7. Final-to-Final изменения

- Добавленное устройство отсутствовало в базовом Final и присутствует в новом.
- Отсутствующее присутствовало в базовом Final и отсутствует в новом.
- Изменение фиксируется только при двух известных и разных значениях.
- Пустое поле не создаёт ложное событие `пусто → значение`.
- Критические поля: IP устройства, IP коммутатора, MAC, физический адрес и
  Smartroom ID.
- Источники и альтернативы не увеличивают число фактических изменений.

## 8. Аналитика

- Устройства, изменённые, отсутствующие и неизменившиеся.
- Перед сравнением Final пустые поля базового снимка можно восстановить из
  предыдущих Final по уникальному сильному идентификатору; конфликтные и
  неоднозначные совпадения не объединяются, источник и дата восстановления
  сохраняются в аналитической копии.
- Производители, модели, помещения и устройства без помещения.
- Помещения с любыми изменениями.
- Помещения, в которых изменилось всё оборудование.
- Изменения устройств типа `Video Conference`.
- Кластеры по производителю, помещению и IP коммутатора включают все группы
  выбранного Final; таблица показывает по 50 групп на странице, CSV содержит
  полный набор кластеров.
- Сетевая топология включает все коммутаторы и порты; для каждого порта доступен
  полный список MAC, производителя, модели, IP, помещения и адреса, по 50
  устройств на странице. Устройства без IP коммутатора доступны в отдельном
  полном списке и также включаются в HTML-отчёт.
- Недельная динамика изменений MAC с количеством помещений и MAC.
- График добавлений и отсутствий показывает сравнение каждого Final со
  следующим наблюдением: добавления выше нуля, отсутствия ниже; первый Final
  является базовым и не создаёт событий.
- Общее число устройств отображается по всем Final от первого до последнего.
- Повторно исчезающие и возвращающиеся MAC рассчитываются по полной истории.
- Текстовый отчёт по производителям, моделям, помещениям и заполненности, TXT
  экспорт и рейтинг помещений рассчитываются по полному выбранному Final.
- Заполненность показывает число распределённых и нераспределённых устройств,
  долю распределённых, число помещений и среднее устройств на помещение.

## 9. Отклонения IP коммутатора внутри помещения

- Помещение группируется по Smartroom ID.
- Если ID отсутствует, используется полный составной ключ ТБ → город → площадка
  → этаж → помещение → адрес.
- Запись без ID объединяется с ID только когда соответствие локации однозначно.
- Если в одной комнате большинство устройств использует один IP коммутатора, а
  часть — другой, комната считается отклонением.
- Карточка `NEW` показывает полный состав: MAC, IP устройства, IP/порт
  коммутатора, производитель, модель, тип, hostname, serial, Device ID,
  Smartroom ID, адрес, время аутентификации и источник.

## 10. Хронология MAC

- Строится по всем последовательным Final.
- Первый снимок показывает заполненное исходное состояние без ложных изменений.
- Далее отображаются все присутствия, реальные изменения и отсутствия.
- Если промежуточный Final пропустил поле, последнее известное значение
  сохраняется для сравнения; возврат того же значения не считается изменением.
- Изменённые поля подсвечиваются, рядом сохраняется полная карточка состояния.

## 11. Хронология помещения

- Каскад: ТБ → город → площадка → этаж → помещение.
- Каждый следующий список содержит значения только выбранной ветви.
- Дополнительный поиск работает по названию, адресу и Smartroom ID.
- Для каждого Final показывается полный состав оборудования помещения.
- Команда сравнивает выбранное помещение в двух последних Final и показывает
  добавления, отсутствия, подтверждённые изменения и неоднозначные личности.
- Пустые поля аналитической копии заполняются только из однозначно
  сопоставленного исторического наблюдения; исходный Final не меняется.
- Отдельная команда показывает комнаты, где изменились все устройства.

## 12. Массовое обогащение

- Пользователь выбирает папки Main, SmartRoom и DDIO.
- Поддерживаются CSV, TSV, TXT, JSON, XLS, XLSX и XLSM; legacy XLS читается локально и ограничен 16 MiB.
- Основные файлы сортируются по дате.
- Автоподбор предлагает режим ближайшей даты с настраиваемым допуском
  (24 часа по умолчанию) или одинаковой календарной даты. Один файл SmartRoom
  или DDIO назначается не более чем одному Main. Import-time fallback не
  считается наблюдаемой датой; неподобранные файлы остаются видимыми.
- Перед запуском показывается таблица пар.
- Источники можно переназначить, а отдельный цикл Main — отключить.
- Для каждого файла отдельно выполняется автоопределение колонок.
- Каждому включённому Main соответствует один последовательный цикл через
  основной enrichment pipeline; каждый успешный цикл создаёт Final.
- Ошибка одного цикла не маркирует частичный Final как успешный.
- Несколько именованных расписаний могут держать независимые копии проверенных
  очередей; запуск задаётся локальным временем или интервалом и может быть
  однократным либо повторяющимся.
- Расписания выполняются последовательно, даже если их времена совпали; каждое
  можно остановить или удалить отдельно. Они работают, пока открыта страница и
  активна инженерная сессия, и не переживают закрытие вкладки.

## 13. Экспорт

- CSV и JSON последнего Final.
- JSON полного результата отдельного анализа и сравнения файлов сериализуется по частям.
- CSV результата поиска.
- Переносимый архив всей локальной базы.
- Импорт архива в другой браузер без удаления уже существующих снимков.

## 14. Темы и ошибки

- Светлая и тёмная темы с контрастными цветами текста.
- Все пользовательские операции обёрнуты в обработку ошибок.
- Ошибка показывается в верхнем баннере.
- Прогресс отражает реальные этапы, а не таймер.
- Операцию обогащения можно отменить через AbortController.

## 15. Горячие клавиши

- Ctrl+O выбирает Main, Ctrl+S выгружает переносимый архив, Ctrl+E экспортирует
  последний Final в CSV, Ctrl+A открывает аналитику, Ctrl+H — хронологию MAC,
  Ctrl+F переводит фокус на поиск.
- F1 открывает руководство; F5 запускает объединение; F6/F9 открывают сравнение
  двух/нескольких файлов; F7/F8 открывают диаграммы/топологию.
- Esc закрывает открытый диалог либо отменяет выполняемую операцию.
- Горячие клавиши перечислены на вкладке «Руководство». Сочетания Ctrl кроме
  Ctrl+F не перехватывают ввод, когда фокус находится в поле формы.

## 16. Аналитика устройства

- Двойной клик по устройству Inventory открывает подробный отчёт со значениями,
  источниками производителя и модели, дополнительными источниками, примечаниями,
  появлениями в Final и событиями History.
- История устройства ищется по сильным признакам; несколько совпадений в одном
  Final явно показываются как неоднозначность.
- Можно открыть хронологию MAC и выгрузить отчёт, появления и изменения в
  самостоятельный HTML-файл. Значения из импортов экранируются перед экспортом.
- Из рейтинга моделей или базы правил можно найти MAC-префиксы точного или
  частичного названия модели. Таблица показывает форматированный префикс,
  название модели, источник правила и количество совпавших устройств выбранного
  Final и производителей.

## 17. Самодиагностика автономного хранилища

- Вкладка «Руководство» запускает read-only проверку IndexedDB: обязательных
  stores и indexes, активного указателя Final, чанков всех Final и количества
  Inventory/History.
- Отдельно отображаются разрешение выбранной папки и оценка квоты браузерного
  хранилища. Проверка не выполняет recovery и не открывает write-транзакции.
- Backend, SQLite и REST API явно обозначаются как отсутствующие в автономной
  browser-only сборке.

## 17. Выбор и контекстные действия таблицы Inventory

- Строки Inventory выбираются мышью, флажками строки/страницы или клавиатурой.
- Меню ПКМ и Shift+F10 копирует MAC, TSV-строку, выбранные строки, видимую
  страницу или весь текущий отфильтрованный Inventory. Полный результат
  сканируется курсором и кодируется фиксированными блоками без массива всех
  устройств. Меню также открывает аналитику устройства или MAC-хронологию.
- При смене поискового запроса выделение сбрасывается, чтобы случайно не
  копировать строки из предыдущей выборки.
- В других таблицах устройств меню ПКМ и Shift+F10 доступно на строке и
  позволяет копировать её MAC/TSV-строку, копировать показанные строки таблицы,
  а также открыть аналитику устройства и MAC-хронологию. Действия, требующие
  выделения Inventory или полного курсорного экспорта, доступны только в
  Inventory.

# Отдельный анализ файла

Экран «Анализ одного файла» разбирает локальную таблицу с настройкой
сопоставления колонок, дедупликацией по сильным идентификаторам, диагностикой
строк без идентичности, сводками по производителям/моделям/помещениям и полным
CSV/JSON экспортом распознанных устройств. Успешный анализ сохраняется снимком
`Single file` с исходным файлом, обновляет Inventory и записывает известные
изменения; он не переключает активный Final и не помечает отсутствующими
устройства, которых нет в частичном файле. Сравнение использует сильные
идентификаторы накопительного Inventory. Отдельная индексируемая история отчётов
содержит полные строки результата и ссылку на снимок; запись можно открыть,
искать, экспортировать и удалить. История переносится вместе с portable database
archive.
Для CSV/TSV/TXT, XLS, XLSX и XLSM mapping определяется по предпросмотру до 80 строк,
а весь файл анализируется пакетами по 500 строк с отображением прогресса и
возможностью прервать устаревший запуск при выборе другого файла или листа.
JSON-массивы и обёртки `devices`, `rows`, `data` также анализируются пакетами.
Неоднозначные строки показывают входные сильные идентификаторы и кандидатов,
не объединяя конфликтующие записи автоматически.

OUI и правила IP коммутатора можно импортировать из CSV/TXT, XLS, XLSX и XLSM.
Книги читаются пакетами по 500 строк; нормализованные OUI-префиксы записываются
в IndexedDB теми же ограниченными пакетами, а правила адресов объединяются по IP. При
импорте IP-маппинга можно подтвердить или вручную задать колонки IP коммутатора
и физического адреса; для OUI можно выбрать колонки префикса и производителя.

Сравнение двух локальных файлов позволяет настроить mapping каждого файла
отдельно и сверить добавления, отсутствия и известные изменения. Неоднозначные
сильные идентификаторы выводятся отдельно и исключаются из счётчиков добавления
и отсутствия. Доступен полный CSV/JSON/Excel/TXT экспорт без записи в базу;
Excel и TXT формируются потоком, включая все категории сравнения.
Для CSV/TSV/TXT, XLS, XLSX и XLSM колонки определяются по предпросмотру до 80 строк,
а оба файла разбираются последовательно пакетами по 500 строк.

Попарное сравнение принимает от двух до десяти CSV/TSV/TXT/XLS/XLSX/XLSM файлов. У
каждого файла собственное сопоставление; список включает оба направления.
Полные данные загружаются только для выбранной пары, экспорт последовательно
собирает общий CSV всех пар. CSV/TSV/TXT, XLS/XLSX и XLSM выбранной пары разбираются
пакетами по 500 строк.

Временная статистика берёт только успешно сохранённые Final и обрабатывает
чанки по порядку. Интервал выбирается как день, неделя или месяц; сводка
показывает уникальные MAC, появившиеся и исчезнувшие MAC, число запусков,
количество устройств и длительность каждого запуска. Таблица и CSV соответствуют
всему выбранному диапазону снимков.
