# Форматы входных данных

Delimited-файлы `.csv`, `.tsv` и `.txt` читаются локально. Разделитель
определяется по расширению TSV или по содержимому остальных текстовых файлов;
для предварительного плана массового импорта хранится только ограниченное
число строк. Полная обработка использует пакеты строк по 500, а потоковый
декодер сохраняет quoted-поля между границами буферов и поддерживает UTF-8,
Windows-1251, UTF-16 и Latin-1 fallback в том же порядке, что и настольный
импортёр.

Книги `.xlsx`, `.xlsm` и старые бинарные `.xls` разбираются локально в браузере.
Для `.xls` автономный комплект содержит SheetJS Community Edition 0.20.3 под
Apache-2.0; книгу можно просмотреть по листам и читать результирующие строки
пакетами, но BIFF-декодер сначала загружает книгу целиком. Поэтому `.xls`
ограничен 16 МиБ до чтения, 150 000 строк и 1 500 000 ячеек. Современные XLSX
сохраняют потоковое чтение XML и ограничения ZIP/общих строк.

JSON-таблицы читаются пакетами по 500 строк как в виде корневого массива, так и
в массивах `devices`, `rows` или `data`. Для объектов заголовки объединяются по
ключам всех записей, поэтому mapping на полном файле совпадает с обычным
JSON-разбором. Дублирующие имена свойств используют полный совместимый fallback.

## Основной файл

Типовые колонки:

- MAC: `CallingStationID`;
- IP коммутатора: `NasIP`;
- порт: `NasPortID`;
- время аутентификации: `B_ReceiptTime`.

Локальные текстовые даты и значения Excel serial нормализуются к ISO 8601.
Для даты выгрузки приоритет такой: дата в имени файла, затем `created` и
`modified` из метаданных книги XLS/XLSX/XLSM, затем `lastModified` файла.
Имя поддерживает даты с разделителями и компактные
`YYYYMMDD` / `DDMMYYYY`, с необязательным временем.

## SmartRoom

- MAC: `MAC`;
- дополнительный MAC: `MAC 2`, `Дополнительный MAC`;
- IP устройства: `IP`, `IP адрес`;
- производитель: `Производитель`;
- модель: `Модель`;
- тип: `Тип модели`, `Тип`;
- адрес: `Адрес локации`, `Адрес комнаты`;
- помещение: `Название комнаты`, `Наименование локации`;
- Smartroom ID: `Smartroom ID локации`, `ID комнаты`.

## DDIO

Используются четыре независимые колонки, а при наличии можно отдельно выбрать
столбец Device ID:

- MAC резервации: `Column3`;
- IP резервации: `Column2`;
- MAC аренды: `Column10`;
- IP аренды: `Column9`.

Device ID связывает строку DDIO только с поисковой информацией `possibleIps`.
Для назначения IP устройства всё равно требуется точное совпадение MAC в паре
MAC/IP. Источник поля `possibleIps` и записи источников устройства указывают
DDIO.

Если в Final отсутствует IP устройства, DDIO ищет точное совпадение MAC в обеих
парах и подставляет IP. IP коммутатора в этом алгоритме не участвует.

## Экспорт Final

Final можно выгрузить в CSV, TXT, XLSX, JSON, YAML и самодостаточный HTML.
Потоковые форматы читают IndexedDB-чанки; при наличии File System Access они
пишутся напрямую в файл с ограниченным буфером. XLSX включает отдельный лист с
метаданными Final и листы устройств; при достижении лимита Excel строки
продолжаются на следующем листе. Печать / PDF открывает подготовленное
представление в диалоге печати браузера, где можно выбрать сохранение в PDF.

## MADB archive

Архив версии 1 проверяется потоковым проходом по корневому JSON до записи в
рабочие хранилища. Затем записи читаются порциями; устройства внутри Final
передаются блоками до 500 строк во временное IndexedDB staging-хранилище.
Optional `originalFiles` сохраняет исходные файлы как последовательность Base64
блоков по 192 КиБ; потоковый reader валидирует каждый блок и размер файла, затем
собирает один Blob в staging. Старые v1 архивы без этой коллекции принимаются.
После полной проверки формат восстанавливается добавочно из staging, а временные
записи удаляются и при успехе, и при ошибке. Импорт ограничен размером файла
4 ГиБ, размером одного оригинала 64 МиБ и числом записей, проверяемых импортёром.

Кнопка «Экспорт для MAC Analyzer Pro» создаёт потоковый `.macarchive.json`
формата `mac-analyzer-full-json` v2. Он содержит метаданные и устройства всех
Final, выбранный активный Final, накопительный Inventory, движения истории и
совместимые настройки темы, Dashboard и детектора производителя. Архив
предназначен для импорта в MAC Analyzer Pro; для полного резервного копирования
всех Next-хранилищ, исходных файлов, моделей и OUI используйте `.madb.json`.

## Legacy SQLite

В portable-приложении есть действие «Импортировать SQLite», доступное в
инженерном сеансе. Оно проверяет заголовок SQLite, потоково сохраняет выбранный
файл в отдельный IndexedDB SQLite VFS, запускает `PRAGMA integrity_check` и
передаёт преобразованные записи через bounded archive importer. Final, Inventory,
OUI, MAC5, IP mapping и данные настроек добавляются; локальное значение имеет
приоритет при конфликте IP mapping. Строки `mac_movements` преобразуются в
идемпотентные события изменения History с MAC и контекстом DDIO. Импортированные
Final остаются в истории, а активный Final сохраняется. Исходный SQLite хранится
в отдельном VFS этого профиля браузера, ссылка на него находится в локальном
`fileHandles`; исходник не попадает в MADB и недоступен в другом профиле браузера.

`mac_history`, `resolved_device_history` и `vendor_model_history` импортируются
в отдельное типизированное хранилище наблюдений с сохранением исходного payload,
источника, MAC/ID и времени. Они включены в portable archive и доступны через
bounded `legacyObservationPage` запросы. При просмотре MAC наблюдения выводятся
отдельными read-only карточками в хронологии и не считаются подтверждёнными
изменениями. Сводка истории производителей и моделей также учитывает vendor/model
поля из `vendor_model_history`, `mac_history` и вложенного `decodedPayload` из
`resolved_device_history`; исходный файл и время наблюдения сохраняются отдельно
от количества Final. Точное совпадение MAC из `vendor_model_history` выбирает последнее
известное значение отдельно для производителя и модели. Для префиксов 5, 4 и 3
байта хранится компактная частотная сводка; выбирается наиболее частое известное
значение, при равенстве — лексикографически первое. OUI/MAC5 имеют приоритет,
confidence и source учитываются отдельно для производителя и модели. Миграция
v16→v17 строит сводку курсором; v17→v18 добавляет индекс сортировки по времени;
v18→v19 добавляет временное IndexedDB-хранилище для exact distinct-сводки без
накопления полного набора значений в памяти. Новые наблюдения обновляют prefix
count в той же IndexedDB-транзакции при импорте, восстановлении и удалении.
Отдельный журнал фильтрует наблюдения по таблице, MAC, источнику, производителю,
модели, помещению и датам; точные totals, счётчики по таблицам и distinct MAC,
vendor, model, room, source охватывают полный результат. Строки читаются
страницами; можно удалить выбранные строки или весь результат активного фильтра.
Очередь заданий и API-кеш остаются открытыми. Отчёты качества сохраняются
отдельно с датой, Final, оценкой и полным расчётом; portable archive переносит их
аддитивно по стабильным ID. Миграция v19→v20 добавляет отдельный store и индексы.
Настройки `results` при отсутствии собственных настроек Next преобразуются в
порядок, видимость и ширину совместимых полей Inventory. Для представлений
`inventory` и `results` точное имя в нижнем регистре имеет приоритет; если его
нет, используется один детерминированный вариант среди имён с другим регистром
или пробелами. Остальные исходные варианты сохраняются в отдельных
collision-safe ключах настроек, поэтому `Results` и `results` не перезаписывают
друг друга. Настройки и исходные варианты входят в portable archive; прочие
представления сохраняются как legacy-данные без применения к интерфейсу Next.
Миграция v20→v21 переносит `legacySmartroomRoom:*` из
настроек в отдельный store, сохраняя исходные записи. SQLite-маппинги помещения
применяются только при точном нормализованном Smartroom ID и пустом текущем
помещении; конфликтующие помещения для одного ID остаются нерешёнными. Источник
и время импортированного значения сохраняются как provenance. Отчёт импорта отмечает
неприменённые таблицы.

Миграция IndexedDB v21→v22 создаёт составной `history.by_mac_timestamp` по
нормализованному MAC и времени, заполняя индексный ключ для уже сохранённых
событий курсором в той же upgrade-транзакции. Хронология устройства использует
этот индекс для прямых MAC-событий и индекс alternate MAC в Inventory для
дополнительных событий по устойчивому ID устройства. Архивный экспорт сохраняет
исходную структуру событий; импорт нормализует индексный ключ при записи.
Таблица `data_quality_reports` переносится постранично и связывает исходный
source, дату, оценку, класс и JSON-отчёт; некорректные строки пропускаются.
Полный паритет SQLite-импорта остаётся открытым до переноса этих функций и
проверки импорта/восстановления в реальном браузере.

Миграция IndexedDB v22→v23 добавляет индексы Inventory по `deviceId` и `serial`.
Они используются вместе с точным внутренним ID, MAC и alternate MAC для
ограниченного поиска кандидатов сильной идентичности; выборка ограничена двумя
записями на ключ, а существующие устройства сохраняются. Это позволяет
сравнивать отдельные наблюдения с накопительным Inventory, не считая отсутствие
устройства в частичном файле его исчезновением.

## IEEE vendor registry

Автономная сборка содержит reference snapshot IEEE Registration Authority,
сгенерированный `2026-10-17`. MA-L, MA-M, MA-S и IAB образуют компактный vendor
lookup; поле `catalog.CID` сохраняет CID Assignment/Organization записи для
справки, но CID не участвуют в определении производителя. Поиск
проверяет 36-, 28- и 24-битный префиксы именно в таком порядке. Сохранённые
пользовательские OUI-правила имеют приоритет при совпадении одинакового префикса.
Reference snapshot обновляется командой `pnpm update:ieee-registry`, которая
загружает MA-L, MA-M, MA-S, IAB и CID, проверяет все ответы и формирует JSON с
датой, количеством записей и SHA-256 каждого источника. Файл заменяется только
после успешной обработки всех пяти источников. Обычная сборка и обработка
оборудования работают офлайн.

Пользовательский CSV/TXT/XLS/XLSX/XLSM импорт префиксов читает таблицу порциями по
500 строк, нормализует каждую порцию и сразу записывает её отдельной транзакцией
IndexedDB. Полный список префиксов из входного файла не удерживается в памяти.
