# Объединение данных и аналитика

## Как получить новый снимок

1. Выберите основной файл от сетевиков в Main. Проверьте колонку MAC: именно она нужна для контроля количества уникальных MAC основного файла.
2. Выберите SmartRoom. Основные поля на экране: MAC, IP устройства, адрес, **Помещение**, серийный номер, тип устройства, модель, производитель, Device ID и ID помещения. Остальные стандартные поля раскрываются через «＋ Дополнительные поля SmartRoom». Их тоже можно сопоставить вручную. Автоподбор является рекомендацией: проверьте названия и примеры перед запуском.
3. Для обычного объединения оставьте «Не увеличивать количество устройств». При открытии программы этот режим включён по умолчанию. Включать расширение состава нужно явно.
4. Выполните объединение. Успешный результат сохраняется целиком в новый снимок. Если проверка или запись завершилась ошибкой, предыдущий успешный снимок остаётся активным.

## Как сопоставляются устройства

Дополнительные поля Main и SmartRoom по умолчанию выключены. Галочка «Учитывать дополнительные поля» разрешает их ручное сопоставление; включение галочки не выбирает колонки автоматически. При снятии галочки назначения дополнительных полей удаляются и данные этих колонок не читаются из источника. Выбор уже занятой колонки переназначает её с уведомлением. Если в старом плане остался конфликт основных полей, сообщение указывает колонку и названия полей — выберите разные колонки или «Не использовать».

Программа нормализует MAC, IP и пустые значения. Для идентификации используются внутренний ID, Device ID, серийный номер и MAC. ID помещения и IP сами по себе не являются идентификаторами устройства. Конфликтующие сильные идентификаторы остаются диагностикой, а не разрешаются случайным выбором строки.

Main задаёт текущий состав. В обычном режиме SmartRoom заполняет поля сопоставленных устройств и не добавляет отсутствующие в Main устройства. Расширение разрешается только отдельным выбором пользователя. DDIO дополняет атрибуты и не создаёт устройств. История может заполнить пустые непротиворечивые поля, но не возвращает отсутствующее устройство в текущий Main.

Полный адрес и назначение помещения — разные признаки. Адрес сохраняется целиком. Для показателя «Без помещения» проверяется только непустое поле **«Помещение»** итоговой таблицы. ID SmartRoom учитывается отдельно и не заменяет название комнаты. Адрес здания без этих признаков сам по себе не подтверждает назначение комнаты.

## Откуда берутся цифры

- Карточка Main показывает количество уникальных нормализованных MAC основного файла выбранного снимка. Повторные строки с тем же MAC не увеличивают это число. Несколько MAC, относящихся по сильному идентификатору к одному устройству, сохраняются как исходные MAC Main.
- Подробная аналитика читает все сохранённые чанки выбранного снимка. Предпросмотр файла не является источником полного расчёта. Повторяющиеся MAC не суммируются повторно в составе аналитики.
- «Без помещения» означает, что поле «Помещение» пустое, даже если ID SmartRoom заполнен. Карточка, детализация и распределения используют одно правило.
- Поиск, производитель и помещение ограничивают текущий состав. Статус сравнения ограничивает только соответствующий список и график производителей статуса; состав текущего Final, заполненность и топология от него не меняются. Над карточками показано, действуют ли фильтры. Для полного состава используйте «Сбросить фильтры» и проверьте выбранный снимок.
- Inventory — накопленный каталог. Его размер не является количеством устройств текущего основного файла.
- Снимки истории и включённые архивы используются для сравнения и динамики. Их количества не складываются в число устройств текущего Main.
- При сравнении двух снимков устройство может быть добавлено, отсутствовать, измениться или остаться прежним. Смена поля требует двух известных разных значений; заполнение прежде пустого поля не создаёт ложное событие изменения.

## Массовое объединение

Выберите обычные файлы Main, SmartRoom и при необходимости DDIO в соответствующих колонках. Для загрузки всей папки есть отдельная кнопка «Выбрать папку». Main находится слева, SmartRoom по центру, DDIO справа; основные поля доступны одновременно без внутренней прокрутки списков колонок.

После выбора Main нажмите «Запустить очередь». Если пары ещё не подготовлены, программа сама прочитает заголовки, сформирует пары и предложит подтвердить запуск. Ошибки сопоставления не позволяют начать запись и показываются рядом с кнопкой. Отмена оставляет подготовленные пары для проверки. Повторный клик во время запуска не создаёт вторую очередь.

Для предварительной настройки можно отдельно нажать «Сформировать пары». Проверьте дату и назначенные источники каждого цикла: неназначенный файл не обогащает результат. При необходимости переназначьте его в списке. Если выбранные SmartRoom/DDIO не назначены всем циклам, подтверждение запуска явно предупреждает об этом. Одна исходная колонка не должна быть назначена одновременно разным полям. Основные правила и стратегия расширения одинаковы для ручного и массового объединения.

Ранее проверенные пары можно подтвердить отдельно либо кнопкой «Подтвердить все корректные пары». Для сохранения расписания по-прежнему требуется проверенная очередь. Пока очередь ожидает запуска или выполняется, её файлы и сопоставление заблокированы от изменений.

Циклы выполняются последовательно. Каждый успешный цикл — отдельный атомарный снимок. Политика очереди определяет, продолжать ли работу после ошибки. Сообщение об ошибке называет пару, файл и этап.

## Архивы и аналитика

Снимки, уже находящиеся в базе, участвуют в истории. Чтобы включить снимки, которые хранятся только внутри локальных архивов, нажмите в аналитике «Включить локальные архивы в аналитику». Программа восстановит их по стабильным ID, обновит выбор снимков и расчёты. Повторное включение не размножает снимки, текущий активный снимок сохраняется. Архивы с другого компьютера сначала импортируются через инструменты базы. Число устройств текущего Main не увеличивается от количества архивных снимков.

## Хронология MAC

Карточка показывает наблюдения выбранного MAC по датам снимков. Первое появление, отсутствие, повторное появление и изменение различаются. При возвращении доступна карточка до исчезновения и карточка после возвращения. Изменения во время отсутствия не выдаются за достоверно наблюдённые события.

Если один MAC связан с несколькими конфликтующими устройствами, программа показывает кандидатов и их полные данные. Она не выбирает одного произвольно. Старые снимки отражают ранее сохранённый результат; для исправления неверного старого сопоставления нужно повторить объединение с исходными файлами.

## Локальный отчёт о багах

В разделе «Аналитика» нажмите «Отчёт о багах (TXT)». Проверка повторно читает все чанки выбранного Final, сверяет счётчики и пустое поле «Помещение» с интерфейсом и расчётом, отмечает адреса, состоящие только из этажа при наличии других частей, и добавляет последние типы технических ошибок. Отчёт сначала отображается для просмотра; «Скачать TXT» сохраняет его локально. Передачи в сеть нет. В отчёт входят только счётчики и фиксированные коды; MAC, IP, адреса, названия файлов, строки устройств, значения фильтров и тексты ошибок не включаются. Журнал технических ошибок автоматически сохраняет последние 100 записей. Отчёт не перечитывает недоступные исходные файлы: для проверки импорта повторите объединение в закрытом сегменте, затем сформируйте отчёт.
