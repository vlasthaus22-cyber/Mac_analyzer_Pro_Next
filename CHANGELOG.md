## Проверка parity — 2026-10-22

- Одиночный анализ адаптивно хранит последовательные ссылки диапазонами, а разреженные — обычным списком, чтобы повторяющиеся записи одного устройства не раздували результат. Предпросмотр показывает диапазон; CSV выводит прежние точные номера порциями, а JSON потоково выдаёт прежний массив `sourceRows`. Старые сохранённые анализы тоже читаются.
- Потоковые Dashboard-проходы теперь нормализуют фильтры один раз и повторно используют matcher для каждой строки; история, churn/trends, выбранная пара, temporal analytics, history search и room rosters больше не пересоздают filter settings на каждом устройстве. Worker-клиент создаёт проекцию и match flags за один проход чанка.
- SQLite migration теперь вычисляет SHA-256 во время обязательного постраничного копирования в SQLite-WASM: большой исходный файл больше не читается целиком вторым проходом. Интеграционная регрессия на реальной SQLite проверяет исходный namespace hash и точный объём чтения; обновление прогресса ограничено пакетами около 256 КиБ, чтобы не тормозить импорт.
- Зафиксирован контракт потокового импорта SQLite-WASM: сначала парсер получает отдельные 32 байта заголовка, затем исходные страницы целиком. Регрессия проверяет точные байты обоих блоков и восстановление нулевого page count; реальный SQLite-WASM импорт и полный `pnpm check` прошли.
- Потоковый архивный импорт пропускает отдельное IndexedDB-чтение перед каждой staging-записью. Регрессия на 500 settings подтверждает ноль `get()` на staging-store; составной primary key по-прежнему отклоняет дубли, а проверки фиксируют отказ и очистку архива.
- Отмена SQLite-импорта теперь передаётся в поток копирования страниц: незавершённая при отмене страница отбрасывается, следующие страницы не читаются, временная SQLite IndexedDB удаляется. Добавлена сквозная регрессия отмены до открытия SQLite.
- SQLite row mapper формирует ограниченные порции до 500 строк вместо 128: для большой базы это уменьшает число промежуточных batch-событий примерно в 3,9 раза при сохранении верхней границы памяти. Тест проверяет точное число порций и максимальный размер.
- SQLite migration получил сквозную регрессию на 10 000 лениво сгенерированных settings rows через production mapper и disposable IndexedDB: проверяются первый/последний значения, точное число записей, отсутствие пропущенных строк и сохранение пустого active Final.

- Сводка одиночного анализа собирает уникальные MAC, заполненность пяти полей и рейтинги производителя/модели/помещения одним проходом вместо девяти проходов по всем устройствам; точные итоги, placeholder и сортировка закреплены существующими regressions.

- Нормализация пустых списков альтернативных MAC и possible IP больше не создаёт временный dedupe Set; тест подтверждает отсутствие аллокации, а существующие правила лимитов и дедупликации сохранены.

Если исходная копия нужна для queued-файла, она остаётся зарегистрированной и доступной. Регрессии покрывают раннее удаление перед production restore и сохранение источника для большого файла очереди.
